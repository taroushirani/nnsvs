Title: Add Python 3.13 support, fix NumPy 2.0 incompatibilities, harden checkpoint loading, and migrate lint tooling from pysen to Ruff

## Summary

This PR brings the project up to date with Python 3.13 and NumPy 2.0, closes a
checkpoint-loading security gap introduced by the PyTorch 2.6 `torch.load`
default change, and replaces the unmaintained `pysen` lint/format tool with
`ruff`. It is organized as a series of small, focused commits; see below for
what each one does and why.

### 1. Python 3.13 support (`fix: support running on Python 3.13`)

- `pyproject.toml`: drop the `numpy`/`cython`/`scipy` build-system requires
  that `setup.py` never actually used. The `numpy<1.20.0` pin in particular
  blocked builds on Python 3.13 entirely.
- `setup.py`: replace the deprecated `SourceFileLoader.load_module()` with
  `importlib.util`.
- `setup.py`: bump `hydra-core` from the 1.1.x to 1.3.x series — the old
  pinned `antlr4-python3-runtime==4.8` imports `typing.io`, which was removed
  in Python 3.13.
- `setup.py`: pin `setuptools<81`, since `pyworld`/`pysptk`/`nnmnkwii` still
  import `pkg_resources` at runtime, and `pkg_resources` was removed from
  setuptools in 82.0.0.
- `nnsvs/util.py`: replace `pkg_resources.resource_filename()` with a
  `__file__`-based path lookup.
- `nnsvs/train_util.py`: update the removed matplotlib style name
  `seaborn-whitegrid` to `seaborn-v0_8-whitegrid`.
- `nnsvs/dsp.py`: pass a scalar `Wn` to `scipy.signal.butter`'s lowpass call
  instead of a single-element list — newer NumPy/SciPy no longer implicitly
  convert a size-1 array to a Python float.
- `nnsvs/gen.py`: convert nnmnkwii's `duration_features()` single-element
  array result via `.item()` before `int()`.
- `.github/workflows/ci.yml`: add a Python 3.13 CI job.

### 2. Remaining NumPy 2.0 / matplotlib fixes (`fix: resolve remaining NumPy 2.0 / matplotlib incompatibilities found via end-to-end recipe runs`)

Running a recipe end-to-end through all stages surfaced further spots where
NumPy 2.0 no longer implicitly converts a non-0-dimensional array to a
Python scalar, plus a matplotlib/NumPy 2.0 incompatibility:

- `nnsvs/train_util.py`: six `ax.set_ylim(...)` calls used builtin
  `min()`/`max()` directly on multi-dimensional lf0/f0 arrays, which return
  sub-arrays instead of scalars; switched the inner reductions to
  `np.min()`/`np.max()`.
- `nnsvs/gen.py`: `postprocess_duration()` subtracted array-valued
  `lag[i-1]`/`lag[i]` from a scalar duration; extract them as scalars via
  `.item()` first.
- `recipes/_common/scaler_joblib2npy_voc.py`: `float()` on a reshaped
  single-element lf0 stream array; use `.item()` instead.
- `setup.py`: `matplotlib<3.6.0` (pinned as a tentative fix for
  https://github.com/nnsvs/nnsvs/issues/191) still uses the removed
  `np.Inf` alias internally, which breaks under NumPy 2.0. Verified that
  issue #191 does not reproduce on matplotlib 3.11.0, so the pin is removed.
- `nnsvs/train_util.py`: switch the seaborn style name back to
  `seaborn-v0_8-whitegrid` to match the unpinned matplotlib version.

### 3. `torch.load` checkpoint security (4 commits)

PyTorch 2.6 changed `torch.load`'s default from `weights_only=False` to
`weights_only=True`. NNSVS checkpoints pickle an OmegaConf `ListConfig`
(from optimizer/scheduler hyperparameters such as Adam's `betas`), which the
restrictive `weights_only=True` unpickler rejects, so every first-party
`torch.load` call site in this repo was pinning `weights_only=False`
explicitly — silently reintroducing arbitrary-code-execution risk on
untrusted checkpoint files.

- `fix: convert optimizer/scheduler params to plain types before instantiation`
  — root-cause fix: `optim_config.optimizer.params` and
  `.lr_scheduler.params` were unpacked directly from an OmegaConf
  `DictConfig` via `**`, so list-valued hyperparameters leaked into the
  optimizer as `ListConfig` objects and got pickled into `optimizer_state`
  on save. Both params dicts are now converted with
  `OmegaConf.to_container(resolve=True)` before being passed to the
  optimizer/scheduler constructors (`nnsvs/train_util.py`, covering both the
  GAN `_instantiate_optim` path and the non-GAN setup path). Checkpoints
  saved from now on no longer need migration.
- `fix: restore weights_only=True default for torch.load call sites` —
  `add_safe_globals` cannot allow `ListConfig` back into the
  `weights_only=True` unpickler (PyTorch hard-codes `SETITEM`/`SETITEMS`
  targets to `dict`/`OrderedDict`/`Counter`, and `ListConfig` uses a
  `defaultdict` internally, so it always fails regardless of the allow-list).
  Packed/distributed inference checkpoints (produced by
  `clean_checkpoint_state.py`) never contain `optimizer_state` and therefore
  no `ListConfig`, so `SPSVS`/`load_vocoder` already load them safely as-is.
  Every remaining first-party `torch.load` call site (resume, synthesis/
  generate/gen_static_features, `clean_checkpoint_state.py`, test fixtures)
  is switched to `weights_only=True`. Old checkpoints saved before this fix
  must be migrated first; two helpers are added for that:
  - `utils/migrate_checkpoint_weights_only.py` — migrates a single
    checkpoint file.
  - `utils/migrate_expdir_weights_only.py` — migrates a
    `pretrained_expdir` directory tree, touching only `latest.pth`/
    `latest_D.pth` since those are the only files the resume path reads.
- `docs: document security trade-off of weights_only=False` /
  `docs: simplify torch.load weights_only section` — document, in
  `docs/devdocs.rst`, what changed in PyTorch 2.6, what was wrong, how it
  was fixed, and how to migrate old checkpoints.

### 4. Migrate lint/format tooling from pysen to Ruff (`build: migrate lint/format tooling from pysen to Ruff`)

`pysen` has been effectively unmaintained since ~2022 and pins very old
`black`/`isort`/`flake8`/`mypy` versions that depend on `typed-ast`/
`lib2to3`, which fail to build on Python 3.13 — this is why lint was
disabled in CI for Python 3.10/3.11/3.13 in the first commit of this PR.

`pysen`'s `black`+`isort`+`flake8` combination (`mypy` was never actually
enabled upstream, and stays disabled here) is replaced with `ruff`, which
natively covers the same rule set (`E`/`W`/`F`/`I`/`B`) with a
black-compatible formatter and has no `typed-ast` dependency, so it builds
cleanly on Python 3.13. `pyproject.toml`, `setup.py`, CI, and
`docs/devdocs.rst` are updated accordingly, and the unused `tox.ini`
`[flake8]` section (never actually applied by `pysen run lint`) is dropped.

All pre-existing lint/format violations uncovered by the new Ruff config are
also fixed in this commit (reformatting plus manual line-length and
missing-`stacklevel`-on-`warnings.warn()` fixes), so that `lint: true`
passes cleanly in CI for every supported Python version.
